# 1.7.21

## 这一版解决什么

DSH Desktop 已经发到 **0.2.2-rc.5**，而这个插件的已验证清单停在 **rc.3**。`rc.4` 一直是 `unknown`，`rc.5` 干脆没登记——于是新装的用户在面板上看到的是「未验证版本」，`selfcheck` 会把补丁层标黄，得自己判断能不能点「应用」。

这一版把 rc.4 / rc.5 补齐，并且**不是"猜能跑"**：在真实 `app.asar` 的解包副本上逐条验完 88 条补丁。

## 验证结论

| 宿主 | 证据 |
|---|---|
| 0.2.2-rc.5 | 88 条补丁 **76 applied / 0 pending / 零漂移**，二次应用 `wrote 0`（幂等）；桌面壳 5 条命中 |
| 0.2.2-rc.4 | 同批零漂移、二次应用 `wrote 0` |

rc.5 的目标源码取自本机真实安装包：`resources/app.asar` 解包后 20,056 个条目，`@deepseek-ai/dsh-desktop` 为 0.2.2-rc.5，`main: lib/main.js`，`dshBuildCommit 3f85d888…`。所以 `Resources/app` 那道布局关卡是按真机形状过的，不是用 npm 包目录凑出来的。

桌面壳 5 条（#45/#46/#82/#83/#84）应用后，`lib/main.js` 里 `[dsh-purge] signal kill`、`[dsh-purge] close no-fail v2`、`verified official installer handoff` 三个标记齐全，旧形态 `dshPurgeHandoffDesktopUpdate` 引用数为 0。

## rc.4 → rc.5 到底改了什么

**只有版本号。** 63 个补丁目标文件里 60 个字节完全一致，剩下 3 个是：

- `dsh-base/cordis.patch.yml` — 交付组合不再固定 `searchProvider`；
- `dsh-base/package.json` — 依赖版本号；
- `dsh-tool-web/lib/index.js` — 搜索/抓取多传一个 `llmProvider` 路由参数。

这 3 个文件涉及的补丁是 #7 / #8 / #21 / #29，锚点在两版上**同样命中**，不需要改补丁，也不需要新增重锚覆盖。rc.3 → rc.4 → rc.5 的官方升级指南（拒答错误码 `MALFORMED_RESPONSE` → `CONTENT_REFUSED`、搜索默认改走 legacy Messages）也都不涉及本插件引用的符号。

## 改动清单

- `lib/community.js`：`QUALIFIED_HOST_VERSIONS` 加入 `0.2.2-rc.5` / `0.2.2-rc.4`（新→旧排序）。
- `package.json`：`dshReleases` 两条 `compatible`；版本与安装 tarball 指向 1.7.21。
- `client.js`：面板版本串重建（只有版本号差异）。
- 文档：`README.md` / `README.zh-CN.md` / `docs/README.en.md` / `AGENTS.md` / `docs/compatibility.md` / `INSTALLATION.md` / `MAINTENANCE.md` 同步版本行与宿主表；补丁条数口径从 86 更正为 88（`ALL_PATCHES` 实际长度）。

## 这一版**没有**做的事（重要）

- **没有在真机上点「应用」，也没有重启 DSH。** 上面所有数字都来自隔离副本的写盘验证。写盘成功 ≠ 进程已加载——要等你自己点「应用」并退出重开，`selfcheck` 才会给出加载后的证据。
- 因此文档里不写「Windows rc.5 真机已加载验证」。rc.4 的桌面壳 5 条也没有单独复测：npm 布局没有 `lib/main.js`，那不是桌面发行版。

## 升级

装好后点「应用」→ 退出并重开 DSH → `selfcheck` 应显示补丁层全绿。若你原本停在 rc.3 且已经应用过旧补丁，官方更新会把 `app.asar` 重新封回去，旧补丁全部失效——这正是需要重新点「应用」的时刻。

测试：`752 tests / 715 pass / 5 fail / 32 skipped`。5 个失败与本版无关：`asar-swap-fallback` 与 4 个 `real Windows PowerShell` 用例在本机因 ExecutionPolicy 禁用脚本、handoff 超时失败，改 rc.5 之前就红。
